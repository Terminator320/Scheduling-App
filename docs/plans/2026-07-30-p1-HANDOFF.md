## The two architecture decisions already made (do not re-litigate)

Both were made by Fable agents against full code recon. They are baked into the plan.

**1. Destination types — split enums under a sealed marker.**
`AdaptiveDestination` (6 members) dies. Replaced by `sealed class AppDestination implements Enum`
with `enum HubTab {calendar, clients, employees, liveMap}` and
`enum PushedDestination {dayRoute, history, dashboard, settings}`, in new files
`lib/core/navigation/app_destination.dart` and `lib/core/navigation/hub_shell_scope.dart`.
Rejected: one-enum-plus-list and one-enum-plus-`isHubTab` — both keep `select(settings)`
compilable, which is the exact runtime crash this restructure exists to prevent.
- **The enum member stays `employees`; only the label becomes "Team"** (new `nav_team` key). A
  rename would break the SharedPreferences tour-seen key (`tour_seen_tabs` stores `.name`) and the
  showcase scope name, for zero user benefit. P4 rewrites that screen anyway.
- **`selectAndReveal` is mandatory, not optional** — from a 2-deep pushed stack, a drawer tap on a
  hub row via the old path leaves the wrong screen on top.
- **`popUntil` targets the shell's *captured* `ModalRoute`, never `isFirst`** — on `_hubRoute`'s
  fallback branch the shell is not route #1.

**2. Token architecture — three extensions plus one new mono extension.**
Placement rule: *a role goes on `ColorScheme` iff Material's own widgets read that slot
implicitly; everything else goes on a `ThemeExtension`.* So `primary` is the saturated **fill**
blue and `palette.primaryAccent` is the text/icon blue; `error` is the lifted **foreground** red
and `palette.dangerFill` is the destructive fill.
- New `AppPalette` (fat, deliberately) + extended `AppStatusColors` (+3 neutral fields) + extended
  `AppCardStyle` (+8 shadow sets) + new `AppMonoType` (10 named mono styles).
- **`google_fonts` is dropped entirely** — both families declared in pubspec, plain `fontFamily:`.
- Crew palette: 10 colours, stored in Firestore as the **light** ARGB int; dark resolves through
  `crewColorOf(theme, storedInt)` against a `crewOverride` map on `AppPalette`. Never store a
  lifted value.

## Things I verified myself — don't re-derive

- Flutter **3.44.1**. `ModalRoute.settingsOf`, `getInheritedWidgetOfExactType`,
  `MediaQuery.accessibleNavigationOf` and `ModalRoute.of` all exist (checked in the SDK source).
- **A closed drawer's child is never built.** `_DrawerControllerState._buildDrawer` returns
  `SizedBox.shrink()` (or a bare drag-detector) while `_controller.isDismissed`. So `ref.watch`ing
  `.autoDispose` count providers inside the drawer body costs nothing while it is closed. **A recon
  agent claimed the opposite — it was wrong.** Do not add an `onEndDrawerChanged` flag to work
  around a cost that does not exist.
- Instrument Sans on Google Fonts is **variable-only**; the statics come from the upstream
  `Instrument/instrument-sans` repo at `fonts/ttf/`. fontsource ships only woff/woff2.

## Deviations made while executing Phase A (already in the code — don't "fix" them back)

1. **`AppMonoType.light`/`.dark` are `static final`, not `static const`.** The plan's
   `const AppMonoType _monoFor({...}) => ...` does not compile — Dart has no const *functions*.
   A const named constructor was tried next and also fails: a const initializer may not
   construct an object (`TextStyle(color: ink)`) from a *parameter*, only from a constant.
   So `AppMonoType._of` is a plain constructor. Consequence: the `ThemeData(extensions: [...])`
   lists in `themes.dart` are **non-const**. Restoring `const` would mean duplicating all ten
   styles per theme.
2. **A3 also retargeted every component theme** (inputs, buttons, dividers, sheets, drawer, FAB)
   off the legacy `AppColors.*` names, because A5 Step 2 expects zero stragglers. It did.
3. **Fixed a latent overflow in `employee_details_view.dart`.** `_ColorRow`'s `Column` was not
   wrapped in `Expanded` (unlike its `_DetailField` sibling), so the larger `labelSmall`
   (9 → 11px) overflowed by 48px at 2× text on a 320px viewport. The row now mirrors
   `_DetailField` exactly. Both text-scale sweeps pass.
4. **`test/employee_color_grid_test.dart` seeds from `AppColors.crewPalette`** now — the old
   `employeePalette` it used no longer exists.
5. `status_pending` was already "Scheduled" / "Planifié" in both ARBs — A4 Step 4 verified, no edit.

## Deviations made while executing Phase B

6. **`SettingsDrawer._goTo` was left hand-rolled**, only its `AdaptiveDestination` annotations
   were retyped to `AppDestination`. It still does `Navigator.pop` + `pushNamed` rather than
   routing through `navigateToDestination`, so a hub-row tap from a 2-deep pushed stack keeps
   the old wrong-screen-on-top behaviour until **Task C2 deletes this drawer**. Deliberate: C2
   replaces the whole widget, so rewiring it in B1 would be thrown away.
7. **`test/features/settings/replay_tour_row_test.dart` swapped `pumpAndSettle` for bounded
   pumps.** Settings is a pushed route now, so clearing the seen flags immediately restarts its
   tour, and the showcase overlay animates continuously — `pumpAndSettle` timed out, and a
   short pump tore the harness down mid auto-scroll (showcaseview then touched a defunct
   `State`). Six 500 ms pumps let the scroll settle. The assertion itself is unchanged.
8. **`test/routes/hub_shell_test.dart` substituted tabs**, per B2 Step 6: the `.settings` case
   became `HubTab.liveMap` and the `.history` case became `HubTab.employees`.
